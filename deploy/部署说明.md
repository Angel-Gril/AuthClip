# Linux 部署

部署包适用于带 systemd 的 Linux x86_64。程序内置前端和 SQLite。示例使用 Caddy 提供 HTTPS，应用监听 `127.0.0.1:8090`。可复用现有反向代理。

## 启动应用

将压缩包上传到服务器的工作目录，解压后执行。

```sh
tar -xzf claude-portal-linux-amd64.tar.gz
cd claude-portal

getent passwd claude-portal >/dev/null || sudo useradd --system --user-group --shell /usr/sbin/nologin claude-portal
sudo install -d -m 0755 /opt/claude-portal/geo
sudo install -m 0755 portal /opt/claude-portal/portal
sudo install -m 0644 geo/country.mmdb /opt/claude-portal/geo/country.mmdb
sudo install -m 0644 claude-portal.service /etc/systemd/system/claude-portal.service
sudo systemctl daemon-reload
sudo systemctl enable --now claude-portal
curl -fsS http://127.0.0.1:8090/api/health
```

把命令中的示例地址换成两个工作台账号的邮箱。终端会分别提示输入密码。

```sh
sudo -u claude-portal /opt/claude-portal/portal account admin@example.com admin --dir /var/lib/claude-portal
sudo -u claude-portal /opt/claude-portal/portal account member@example.com member --dir /var/lib/claude-portal
```

## 配域名和 HTTPS

把域名的 DNS 记录指向服务器，并让反向代理接收公网的 80 和 443 端口。在 `Caddyfile.example` 中把 `portal.example.com` 改成实际域名，将整个站点块合并到现有的 `/etc/caddy/Caddyfile`。

```sh
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile
sudo systemctl reload caddy
curl -fsS https://portal.example.com/api/health
```

如果已经有 Nginx，可以继续使用。在对应站点中将请求转发给 `http://127.0.0.1:8090`，用 `proxy_set_header X-Real-IP $remote_addr;` 覆盖客户端传入的同名头，并为 `/api/realtime` 关闭代理缓冲。若还有一层 CDN，先在外层代理配置其可信地址范围，再把验证后的访客地址传给应用。

用 HTTPS 域名打开页面并复制任务链接。用两个工作台账号分别登录，确认接收人能打开任务，A 端能看到 B 端的实时反馈。

## 数据和升级

工作台数据在 `/var/lib/claude-portal`。升级前暂停服务，备份此目录和上一版程序，再替换程序并启动。若需要回滚，恢复相互匹配的上一版程序和备份。工作台按 7 天清理已确认记录，外部备份的保留期由服务器维护者设置。

```sh
sudo systemctl status claude-portal
sudo journalctl -u claude-portal -n 100
```

包内公网 IP 归属数据库来自 DB-IP Country Lite（CC BY 4.0）。后续可用同款 MMDB 文件替换 `/opt/claude-portal/geo/country.mmdb` 并重启服务。[DB-IP Country Lite](https://db-ip.com/db/download/ip-to-country-lite)
